# 透明物品结果页自适应设计

## 目标

调整“制作透明物品”结果页，使原始照片和透明物品在手机横屏窗口中完整显示，同时尽量避免弹窗内部滚动。

本轮只修改结果页 UI，不处理鱼停止运动的问题。

## 交互范围

- “返回修改”按钮文案改为“重新生成”。
- 点击“重新生成”后仍返回上一页，允许用户修改图片、描述、类型、名字或放置方式。
- 不在结果页直接再次调用 AI，不改变现有生成请求、取消处理和确认放入鱼缸的业务流程。

## 布局设计

### 弹窗

- 弹窗尺寸受当前视口宽高约束，并优先在一个横屏视口内完整展示标题、预览、操作按钮和状态文字。
- 结果页采用纵向弹性布局：标题和底部操作区占用内容所需高度，中间预览区使用剩余空间。
- 常见手机横屏尺寸不产生内部滚动。
- 仅在极端矮屏或系统字体显著放大、导致所有必要控件无法同时容纳时，保留纵向滚动作为可访问性兜底。

### 对比预览

- 原始照片和透明物品保持左右并排，两列等宽。
- 预览区域高度由可用视口高度动态决定，不再使用单一固定像素高度。
- 每个预览容器允许自身缩小，并设置合理的最小高度，避免挤压标签或操作按钮。
- 原始照片和透明结果 Canvas 均占满预览容器的 CSS 内容框，并使用 `object-fit: contain`。
- 图片保持原始宽高比，完整显示；允许出现留白，禁止裁剪和拉伸。
- 透明结果继续使用棋盘格背景，以便辨认透明区域。

### 紧凑横屏

- 当视口高度较小时，减少弹窗内边距、标题区间距、预览标签间距、操作区间距和按钮高度。
- 预览仍保持双列，不切换为竖排，符合项目的手机横屏主适配要求。
- 操作按钮始终可见，不覆盖预览内容，也不造成横向滚动。

## 实现边界

- 修改 `game/styles.css` 中结果页、预览区、操作区和矮屏媒体查询的布局规则。
- 修改 `game/index.html` 中按钮文案。
- 保留 `game/js/app.js` 里 `backToCapture()` 及其事件绑定，不改变按钮行为。
- 不修改图片生成、透明通道、Canvas 像素数据或 AI Agent API 调用。

## 错误与兜底

- 现有生成中、生成失败、取消处理和确认放入的状态继续使用原有逻辑。
- 图片或 Canvas 内容尺寸异常时，CSS 仍将其限制在预览容器内。
- 极端矮屏允许弹窗纵向滚动，确保关闭、重新生成和确认按钮可操作。

## 验收标准

- 常见横屏尺寸（至少覆盖 1280×720、844×390、667×375）中，结果弹窗主要内容无需内部滚动即可操作。
- 原始照片与透明物品均完整显示，没有顶部、底部或左右裁切。
- 两侧预览不变形，透明物品棋盘格可见。
- “重新生成”按钮返回上一页，不会自动发起新请求。
- “确认放入鱼缸”按钮保持可见可用。
- 页面没有横向滚动条，生成中和错误状态布局没有回归。
