# 自定义鱼宽高比双方向摆动设计

## 目标

当用户把抠出的透明物体转化为鱼时，继续沿用现有鱼的游动路线、行为状态和交互，只根据透明物体的实际宽高比切换 WebGL 网格的形变方向：

- 高大于宽：使用海草式左右摆动。
- 宽大于或等于高：使用鱼式上下摆动。

## 现状

自定义鱼已经保存透明图片的 `aspectRatio`，并通过 `AquariumWebGLFishMesh` 使用统一网格和顶点着色器渲染。当前着色器仅支持沿横轴传播、顶点上下位移的鱼式波浪。Canvas 会在 WebGL 不可用或对象被选中时提供静态兜底。

## 方案

扩展现有 WebGL 网格着色器和渲染参数，不新增第二套渲染器。

### 运动模式

渲染器接收一个由宽高比推导出的运动模式：

- `fish`：`aspectRatio >= 1`。波浪沿纹理横轴传播，顶点主要沿纵向位移，保持现有鱼式上下摆动。
- `seaweed`：`aspectRatio < 1`。波浪沿纹理纵轴传播，顶点主要沿横向位移。形变强度从底部向顶部增加，使视觉更接近海草随水流左右摆动。

正方形物体归入 `fish`，保证边界判定稳定且与“高大于宽”这一严格条件一致。

### 数据流

1. 抠图生成后继续以 `naturalWidth / naturalHeight` 计算并保存 `aspectRatio`。
2. `drawFish` 根据 `aspectRatio` 选择 `fish` 或 `seaweed`，并把模式传给 WebGL 渲染器。
3. WebGL 渲染器把模式转换为着色器 uniform。
4. 顶点着色器在同一套网格中选择对应的传播轴、位移轴和锚定权重。
5. 位置更新、觅食、漫游、受惊、翻转、大小调整和存档逻辑保持不变。

### 形变细节

- 鱼式模式保留当前尾部权重、头部稳定度、速度相关振幅和频率。
- 海草式模式以纹理底部为稳定端，向顶部逐渐增强左右位移。
- 海草式模式不改变图片原始朝向，也不旋转纹理。
- 两种模式都遵守现有 `prefers-reduced-motion` 降低振幅和频率的规则。
- 选中编辑时继续使用静态图片，避免控制框随网格形变抖动。

### 摆幅调校

- 以首版双方向形变的振幅为基准，`fish` 模式的上下摆幅使用 1.8 倍。
- 以首版双方向形变的振幅为基准，`seaweed` 模式的左右摆幅使用 2.0 倍。
- 仅调整形变振幅，不改变波动频率、游动路线、速度、行为状态或交互。
- `prefers-reduced-motion` 继续在增强后的模式振幅上应用现有降幅。
- WebGL 离屏画布为两种最大摆幅保留安全边距，避免顶点在峰值时被裁切。

## 兼容与兜底

- 缺少或无效的 `aspectRatio` 时，从图片 `naturalWidth / naturalHeight` 重新计算。
- 宽高比仍无效时默认使用 `fish`。
- WebGL 初始化、纹理上传或渲染失败时继续使用现有静态 Canvas 兜底。
- 旧存档无需迁移；已保存宽高比的自定义鱼会自动得到对应模式。

## 测试

采用测试驱动实现，至少覆盖：

1. 宽图选择 `fish` 模式。
2. 竖图选择 `seaweed` 模式。
3. 正方形选择 `fish` 模式。
4. 无效宽高比默认选择 `fish`。
5. 两种模式都产生非零、受行为速度和减少动态偏好约束的运动参数。
6. 着色器包含方向 uniform，并保留现有纹理朝向和 WebGL 不可用兜底测试。
7. 在相同速度和行为输入下，`fish` 模式使用 1.8 倍振幅、`seaweed` 模式使用 2.0 倍振幅，且两者频率一致。
8. 完整测试、类型检查和构建全部通过。

## 不在范围内

- 不把竖图固定成扎根装饰物。
- 不改变鱼的路线、速度、觅食或交互行为。
- 不增加用户可见的模式开关。
- 不修改后端抠图或对象识别接口。
