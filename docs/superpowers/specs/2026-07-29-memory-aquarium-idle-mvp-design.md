# 私人记忆生态缸放置玩法 MVP 设计

日期：2026-07-29

状态：已获用户口头批准，等待书面规格复核

目标版本：参赛/演示 MVP

目标平台：移动端横屏互动空间 H5

包体目标：无 8 MB 硬限制，静态产物尽量控制在 20 MB 内

## 1. 产品定位

作品的核心不是传统数值养鱼，而是“装着玩家现实生活的私人记忆生态缸”。玩家把自己拍摄的现实物品放入水中，鱼和物品在在线、离线时间里建立关系并产生简短故事。放置收益、投喂、解锁和远游都用于推动记忆内容继续生长。

核心体验比例为：

- 70% 私人记忆、关系和故事；
- 30% 放置、成长和解锁。

作品保持原创视觉与叙事，不复用任何现有养成作品的角色、界面、名称或受保护素材。

## 2. MVP 范围

### 2.1 包含

- 沿用现有横屏生态缸、鱼群行为、现实物品抠图和摆放能力；
- 在线与离线饲料收益；
- 饲料投喂、装饰、预设鱼和现实物品容量解锁；
- 现实物品容量 `3 → 5 → 7 → 9`；
- 约 10 类本地事件骨架；
- 本地事件导演与 AI 动态故事；
- 现实物品落稳后的黑底白字即时事件；
- 最多同时显示 3 个离线关系气泡与双实体事件卡；
- 鱼—物品、鱼—鱼、物品—物品关系；
- 两个有效事件即可完成的快速成长；
- 关系建立后的轻微位置绑定；
- 成鱼“留下 / 远游”选择、一次性成长奖励和旅途纪念；
- 生态缸纪念海报生成、预览和本地保存；
- `localStorage + IndexedDB` 本地存档；
- AI、存储、图片和运行时异常兜底。

### 2.2 不包含

- 账号系统、云存档和跨设备同步；
- 排行榜、好友鱼缸和多人联机；
- 广告、付费、盲盒和概率抽取；
- 每日签到、复杂任务树和强制回流；
- 站外跳转、二维码、联系方式和营销导流；
- 原生地理位置、麦克风、视频、文档等输入。
- 独立记忆册、故事筛选和现实物品故事时间线。

## 3. 核心循环

```text
在线/离线积累饲料
        ↓
查看归来时发生的新故事
        ↓
投喂鱼、推进成长与关系
        ↓
解锁装饰、预设鱼、现实物品容量
        ↓
放入新的现实物品
        ↓
产生鱼—物品、鱼—鱼、物品—物品关系
        ↓
成鱼选择留下陪伴或远游腾出位置
        ↓
生成生态缸纪念海报
```

放置经济只服务于放入更多现实物品、观察更多关系和保存更多记忆，不制造重复劳动或数值压力。

## 4. 首次 3–5 分钟体验

1. 玩家进入已有鱼群的生态缸，获得 20 份初始饲料。
2. 玩家点击现有“放入”按钮，拍摄或从相册选择现实物品。
3. 玩家填写物品描述，并可选择填写时间、地点。
4. AI 完成目标定位和透明抠图，玩家确认后放入生态缸。
5. 物品入缸后立即播放本地行为并触发第一个有效事件。
6. 现有黑底白字故事条立即展示模板短句，AI 在后台生成正式的 40–80 字故事并原位替换。
7. 玩家投喂一次，增加 25 成长度并提高下一事件触发概率。
8. 60–120 秒内触发第二个有效关系事件，鱼成长完毕。
9. 玩家获得故事奖励，可购买一个小型装饰或继续积攒容量升级所需饲料。
10. 成长后的鱼出现“留下 / 远游”选择；两种选择奖励相同，不会自动离开。

## 5. 饲料经济

### 5.1 收入

| 来源 | MVP 基线 |
| --- | ---: |
| 初始赠送 | 200 |
| 在线挂机 | 基础每 45 秒 1 份，受活跃鱼和亲密度加速 |
| 离线挂机 | 基础每 4 分钟 1 份，受活跃鱼和亲密度加速 |
| 离线收益上限 | 8 小时；最高 3 倍时最多 360 份 |
| 放入首件现实物品 | 10 |
| 普通故事 | 4–8 |
| 深度关系故事 | 10–16 |
| 成鱼成长完成奖励 | 30–60 |
| 首条教学鱼成长纪念奖励 | 额外 20 |

离线收益公式：

```text
收益倍率 = min(3, 1 + 活跃鱼数量 × 0.15 + Σ(活跃鱼亲密度 / 100 × 0.35))
有效离线时间 = min(max(当前时间 - 上次保存时间, 0), 8小时)
饲料收益 = floor(有效离线时间 / (4分钟 / 收益倍率))
```

只有留在鱼缸里的活跃鱼参与收益倍率计算，远游鱼不再提供加速。时间倒退、异常跨度或存档字段损坏时，本次离线收益归零，但不扣除已有饲料。

### 5.2 支出

| 用途 | MVP 基线 |
| --- | ---: |
| 投喂一次 | 4 |
| 小型装饰 | 20–35 |
| 中型装饰 | 45–70 |
| 预设鱼 | 50、90、140 |
| 实物容量 3→5 | 60 |
| 实物容量 5→7 | 120 |
| 实物容量 7→9 | 220 |

预设鱼采用一次性解锁。成鱼奖励只结算一次，不设计通过重复选择留下、远游或重新放入来回收饲料的套利循环。

石洞首次解锁价为 `10`（原价 `20`）、旧陶罐首次解锁价为 `35`（原价 `50`）、铜蓝斗鱼首次解锁价为 `30`（原价 `50`）。商店 ViewModel 同时返回折扣价、原价和新手折扣标记。

## 6. 快速成长与成鱼选择

### 6.1 成长规则

- 成长度范围为 `0–100`；
- 鱼与玩家的亲密度 `affection` 范围为 `0–100`，与鱼—鱼、鱼—物关系图分开保存；
- 每个有效故事事件增加 50 成长度；
- 每次投喂增加 25 成长度和 5 亲密度；
- 正式长成必须同时满足“成长度达到 100”“亲密度达到 100”和“有效事件数至少为 2”；
- 如果成长提前到达 100，但亲密度或事件数未满足，则显示为 99；
- 首条陪伴鱼初始为 99 成长度、99 亲密度并已有 2 个有效事件；首次投喂后立即发出 `maturity:ready`，进入“成熟抉择”；
- 成熟抉择仍由玩家选择留下或远游，不会自动让鱼离开。

有效事件包括：

- 指定鱼参与现实物品入缸；
- 鱼与物品建立关系；
- 两条鱼共同探索物品；
- 两个现实物品产生关联；
- 关系阶段达到新阈值；
- 其他由本地事件导演确认的非重复正式故事。

普通游动、重复进食动画和没有关系变化的微反馈不计入成长事件。

### 6.2 留下或远游

鱼完成成长后，玩家获得一次 `30–60` 份饲料的成长奖励，并选择“留下”或“远游”。奖励根据成长和关系计算，但与选择无关，只能领取一次，因此选择表达的是“继续陪伴还是腾出位置”，不会变成奖励最优解。

选择“留下”：

- 鱼继续生活在当前生态缸中；
- 继续占用一个活跃鱼位；
- 生成一张即时展示的“留下陪伴”成长故事卡；
- 可以继续参与关系事件和海报；
- 以后仍可改为远游，但不会再次获得成长奖励。

选择“远游”：

- 鱼从当前生态缸离开并释放鱼位；
- 生成一张即时展示的告别故事卡；
- 最亲近的现实物品进入告别故事；
- 远游记录和相关故事继续保存在本地存档中；
- MVP 额外生成一次旅途来信。

状态字段：

```javascript
{
  maturityRewardClaimed: true,
  maturityChoice: "stay", // "stay" | "journey"
  journeyStartedAt: null
}
```

规则：

- 成长奖励在首次确认成鱼去向时结算；
- `maturityRewardClaimed` 为 `true` 后，不得因切换去向重复发放奖励；
- “留下 → 远游”是允许的单向变化；
- 已远游的鱼在 MVP 中不能返回主缸；
- 玩家可以无限期保留成鱼，不设置强制离开或惩罚。

## 7. 事件导演

### 7.1 十类故事骨架

1. 初次见面；
2. 用途误解；
3. 躲藏休息；
4. 玩耍探索；
5. 鱼—物品友谊；
6. 鱼—鱼共同事件；
7. 物品—物品联想；
8. 环境变化；
9. 深度陪伴；
10. 成鱼选择、陪伴与远游。

骨架只定义参与者、行为、情绪、触发条件和状态变化，不保存固定成品文案。

### 7.2 选择流程

```text
收集当前鱼缸状态
→ 筛选满足前置条件的骨架
→ 排除冷却中和近期重复事件
→ 按关系、位置、成长需求和时间加权
→ 用存档种子确定事件
→ 立即播放本地行为
→ 本地结算成长、关系和奖励
→ 调用 AI 写作
→ 保存正式故事或模板回退
```

AI 不拥有修改饲料、成长、关系、位置或存档规则的权限。

### 7.3 频率

- 入缸事件：必定立即发生；
- 首轮第二事件：首次体验中 60–120 秒触发；
- 后续在线微事件：约 2–4 分钟一次；
- 后续正式关系故事：至少间隔 8 分钟；
- 离线事件：每 2 小时最多 1 个；
- 单次归来最多补算 3 个故事。

现实物品到达玩家选择的 `bottom / suspended / surface` 位置并完成落稳动画后，立即触发一次入缸随机事件。该事件使用现有黑底白字故事条，不打开事件大卡片；本地模板先显示，AI 返回后原位替换正文。

离线事件不直接塞进黑底故事条。玩家回到鱼缸后，未读的鱼—鱼、鱼—物或物—物事件以聊天气泡显示在参与者之间，最多同时显示 3 个。气泡出现时使用两个参与实体当前位置的中点作为锚点，重叠时自动错开；位置只低频更新，不进入每帧布局计算。

存档保存最近 20 个事件指纹：

```text
骨架类型 + 参与者组合 + 主要隐喻
```

同一指纹至少经过 5 个其他故事后才允许再次出现。

## 8. AI 故事

### 8.1 模型

文本和已确认适用的图片理解调用使用：

```text
doubao-seed-2-1-turbo-260628
```

正式互动空间版本通过平台确认可用的 `tt.*` Agent 能力调用，不直接向模型服务发送 HTTP 请求。开发期现有后端诊断链路可以保留，但不进入正式静态产物。

### 8.2 输入

每次只提供必要结构化信息：

- 事件骨架；
- 参与鱼的名字、成长阶段和性格标签；
- 参与物品的名称、识别标签和水中状态；
- 玩家主动提供的时间、地点；
- 当前关系阶段；
- 明确的字数、风格和安全要求。

未提供的时间、地点和私人经历不得自行虚构。图片只用于已声明的 AI 抠图或理解链路，故事阶段优先使用已经确认的文本标签。

### 8.3 输出

期望输出：

```json
{
  "title": "一小块屋檐",
  "body": "旧车票落进水里后，月白绕了两圈，最后安静地停在下面。它大概不知道杭州，只觉得这里刚好能遮住一点水光。",
  "posterLine": "有些走过的路，会在水里变成屋檐。"
}
```

约束：

- 正文 40–80 个中文字符左右；
- 轻盈、克制、有画面感，不堆砌形容词；
- 不虚构未提供的隐私信息；
- 不包含营销、联系方式、站外引导和侵权内容；
- 不重复近期主要隐喻；
- 返回内容需通过结构、长度和安全校验。

### 8.4 即时反馈与回退

- 本地行为和模板短句立即展示；
- AI 在后台生成正式故事；
- 单次等待超过 12 秒、解析失败或内容不合格时使用模板版本；
- AI 失败不撤销成长、关系、饲料和事件历史；
- MVP 不提供手动重新生成入口；回退故事直接作为本次正式结果保存，且不重复发放奖励。

## 9. 关系与位置软绑定

支持：

- 鱼 ↔ 现实物品；
- 鱼 ↔ 鱼；
- 现实物品 ↔ 现实物品。

关系阶段：

| 数值 | 阶段 |
| --- | --- |
| 0–24 | 陌生 |
| 25–59 | 注意到了 |
| 60–89 | 好朋友 |
| 90–100 | 特别的陪伴 |

关系值来源：

- 共同参与有效事件：`+25～35`；
- 在附近共同进食：`+8`；
- 在线长时间相处：少量增加；
- 离线正式事件：`+15～25`；
- 重复刷同类行为：不增加。

关系达到“好朋友”后：

- 鱼有约 35% 的空闲时间回到关系物品附近；
- 两条鱼偶尔共享游动目标；
- 两个可移动悬浮物体产生轻微吸引但不重叠；
- 沉底、水面固定物品不被系统擅自移动；
- 玩家编辑时绑定暂停，结束编辑后重新计算；
- 所有绑定均为可打断的软约束。

## 10. 本地存档

### 10.1 `localStorage`

保存：

- 饲料和离线时间；
- 容量等级与解锁项；
- 鱼（含亲密度）、物品和装饰的结构化状态；
- 关系图；
- 事件历史和故事；
- 最多 3 个未读离线事件、参与者 ID、气泡锚点和已读状态；
- 成鱼选择、成长奖励领取状态和远游记录；
- 设置与版本信息。

业务 key：

```text
stubborn_fish_state_v1
stubborn_fish_state_backup_v1
```

### 10.2 `IndexedDB`

保存：

- 透明现实物品图片；
- 自定义鱼图片；
- 必要的记忆缩略图。

不长期保存原始照片。抠图结果最长边约 768 px，单件目标控制在约 100–400 KB。海报按需生成，不重复保存在存档中。

### 10.3 保存与恢复

在以下时机保存：

- 资源获得或消费；
- 鱼成长、选择留下或开始远游；
- 物品加入、删除或编辑；
- 关系和故事完成；
- 拖动结束后防抖 500 ms；
- 页面进入后台或关闭；
- 在线状态每 30 秒低频兜底。

存档包含 `schemaVersion`、`savedAt`、`lastActiveAt` 和 `stateId`。读取时校验主存档，失败后读取备份；图片丢失时显示通用剪影，不导致白屏。

本地存档不承诺跨设备同步。清理宿主应用数据、浏览器存储或卸载宿主可能造成存档丢失，作品内需明确说明。

## 11. 界面设计

### 11.1 主界面

主界面沿用当前实现，不重做布局：

- 保留全屏鱼缸 Canvas；
- 保留顶部品牌、背景和声音按钮；
- 保留底部 `投喂 / 放入 / 观赏`；
- 投喂按钮附带饲料余额；
- 放入按钮附带现实物品容量，如 `2/3`；
- 顶部操作区只增加商店入口；
- 海报入口放在现有“观赏”模式内；
- “留下 / 远游”入口位于成熟鱼的信息卡；
- 继续使用现有故事浮卡和鱼、物品、装饰编辑工具。

### 11.2 放入流程

沿用现有弹层并扩展为：

1. 选择现实物品，填写描述及可选时间、地点；
2. 查看原图与透明结果并选择水中状态；
3. 确认入缸，播放动画并触发即时事件。

不调用原生地理位置。所有输入只用于已声明的 AI Agent 处理。

### 11.3 商店

标签为：

- 装饰；
- 预设鱼；
- 实物容量。

商店只使用明确标价，不使用随机抽取。购买的装饰和预设鱼进入“已拥有”目录，由玩家决定是否放入。

### 11.4 即时事件与离线事件

即时入缸事件：

- 现实物品落稳后触发；
- 使用现有黑底白字故事条；
- 不阻挡继续布置鱼缸；
- AI 生成失败时保留模板回退文案。

离线关系事件：

- 单次归来最多产生并同时显示 3 个未读气泡；
- 鱼—鱼、鱼—物、物—物都可以形成气泡；
- 气泡位于两个参与实体的中点上方；
- 多个气泡重叠时沿纵向错开，仍放不下时靠近安全区边缘；
- 点击某个气泡时，其他气泡暂时隐藏并打开事件卡；
- 返回鱼缸后，已查看气泡消失，其他未读气泡恢复；
- 未点击的气泡写入本地存档，刷新后继续显示。

事件卡固定结构：

```text
两个参与实体的图标、照片或本地剪影
事件标题
AI 生成或模板回退的 40–80 字正文
“转发事件”按钮
“返回”按钮
```

事件卡不提供重新生成、点赞、评论、站外跳转或纪念册入口。

## 12. 纪念海报

MVP 提供一套 `1080 × 1440` 竖版海报：

- 顶部：作品标题与日期；
- 中部：隐藏 UI 后的鱼缸截图；
- 下部：一篇选中的记忆故事；
- 底部：AI 生成或模板回退的小清新短句。

海报不包含二维码、联系方式、营销语、外链或强制分享提示。

MVP 不提供故事列表选择。生成海报时优先使用当前正在展示的故事；当前没有故事卡时使用最近一篇已经保存的故事；存档中也没有故事时使用内置的生态缸默认短句。

离线事件卡的“转发事件”复用同一海报渲染器，但内容固定为当前事件：

- 两个参与实体的图标、透明照片或本地剪影；
- 事件标题、AI 正文和日期；
- 生态缸截图或本地水色背景；
- 不包含二维码、联系方式、外链和强制分享提示。

“转发事件”在 MVP 中表示生成并保存事件海报到本地，不直接发布到站外。平台相册接口不可用或权限被拒绝时，显示完整预览并提示长按保存。

流程：

```text
隐藏操作 UI
→ 离屏 Canvas 重绘鱼缸
→ 叠加日期、故事和纹理
→ 生成 PNG 临时图片
→ 显示作品内预览
→ 用户主动保存到相册
```

正式实现前确认互动空间 H5 运行环境是否暴露相册保存能力。支持时调用平台接口；不支持或授权失败时保留完整预览并提供长按保存兜底。

## 13. 代码边界

保留现有渲染和抠图代码，新增模块：

```text
game/js/
├── app.js
├── cutout-flow.js
├── object-segmentation.js
├── webgl-fish-mesh.js
├── aquarium-api.js
├── state-store.js
├── economy-system.js
├── relationship-system.js
├── story-template-catalog.js
├── story-template-registry.js
├── event-director.js
├── story-agent.js
├── growth-journey.js
└── poster-renderer.js
```

职责：

- `app.js`：初始化、Canvas 循环和模块协调；
- `aquarium-api.js`：前端按钮调用的稳定函数门面，未完成能力统一返回 `NOT_READY`；
- `state-store.js`：本地持久化、迁移和备份；
- `economy-system.js`：挂机、饲料、支出和容量；
- `relationship-system.js`：关系图和位置软绑定；
- `story-template-catalog.js`：故事策划独立维护的纯数据模板，不包含玩法规则；
- `story-template-registry.js`：模板校验、选择、占位符渲染和通用回退；
- `event-director.js`：事件筛选、频率、冷却和去重；
- `story-agent.js`：平台 AI 调用、校验和模板回退；
- `growth-journey.js`：快速成长、成鱼选择、一次性奖励和远游；
- `poster-renderer.js`：离屏海报合成。

新增模块优先使用与现有项目一致的浏览器 IIFE/全局命名空间模式，避免在同一功能中同时引入新的模块体系。现有 `app.js` 只做与新增模块接线相关的局部整理，不进行无关重写。

故事模板与玩法逻辑必须分离。故事策划可以在 `story-template-catalog.js` 中随时增加、修改、停用同一事件类型下的文案骨架、提示词和 fallback，不需要修改 `event-director.js` 或 `story-agent.js`。新增奖励、参与者类型、Canvas effect 或全新触发规则时，才需要后端配合。

## 14. 错误处理

- 应用初始化失败：显示“哎呀，出错了，请重启试试”兜底页；
- AI 不可用：立即使用模板故事；
- AI 输出无效：丢弃模型结果，不改变本地状态；
- IndexedDB 不可用：当前会话可继续，提示图片无法长期保存；
- 存储空间不足：降低新图片尺寸后重试一次，仍失败则保留旧存档；
- 图片引用丢失：显示通用剪影；
- 相册保存被拒绝：保留海报预览；
- 时间异常：取消本次离线收益；
- 任意弹层：使用作品自绘覆盖层，不使用原生阻塞对话框；
- 所有失败都不得导致白屏、资源倒扣或存档被无提示覆盖。

## 15. 性能与包体

- 主流移动设备目标帧率不低于 30 FPS；
- 压力场景为 9 件现实物品、多条鱼、食物粒子和关系行为同时运行；
- 关系计算按低频 tick 执行，不进入每帧全量两两扫描；
- AI 调用、存档和海报生成不得阻塞渲染循环；
- 图片进入 IndexedDB 前缩放压缩；
- 静态资源使用本地相对路径；
- 不引入大型第三方库、远程字体、CDN 和远程媒体；
- 静态产物尽量控制在 20 MB 内；
- 根目录直接包含唯一入口 `index.html`。

## 17. MVP 验收标准

- 新玩家 3 分钟内看到首个正式或回退故事；
- 5 分钟内可以触发第二个有效事件并完成成长；
- AI 失败不阻断任何核心操作；
- 现实物品容量严格按 `3 → 5 → 7 → 9` 解锁；
- 离线收益正确且不超过 8 小时，收益倍率不超过 3 倍；
- 刷新后饲料、物品、故事、关系、成长和解锁状态保留；
- 成鱼可以选择留下或远游，两种选择获得相同的一次性成长奖励；
- 留下继续占用活跃鱼位，远游释放鱼位且历史不丢失；
- 先留下再远游时不得重复获得成长奖励；
- 关系达到阈值后出现可见但可打断的位置行为；
- 海报包含鱼缸、日期、故事和短句；
- 现实物品落稳后使用现有黑底白字 UI 立即显示随机事件；
- 离线归来最多同时显示 3 个双实体关系气泡；
- 点击气泡可查看事件卡，并可将当前事件保存为本地海报；
- 最大内容场景在目标设备稳定达到 30 FPS；
- 正式产物无非指定网络请求、外部资源、站外跳转和 `iframe`；
- 静态产物尽量控制在 20 MB 内。

## 19. 风险与对策

| 风险 | 对策 |
| --- | --- |
| AI 生成慢 | 本地行为和短句先展示，12 秒回退 |
| AI 故事重复 | 保存最近 20 个事件指纹并降低重复权重 |
| AI 虚构地点 | 未提供字段不得进入故事事实 |
| 存档被清理 | 明示本地存档边界，维护主存档和备份 |
| 图片占用过大 | 只保存压缩透明结果，不保存原始照片 |
| 快速成长造成经济膨胀 | 成长奖励封顶且只结算一次，预设鱼一次性解锁 |
| 玩家只按奖励选择去向 | 留下与远游奖励完全相同，差异只在陪伴和鱼位占用 |
| 鱼缸拥挤 | 容量封顶 9，使用分层绘制和软碰撞 |
| 相册接口不可用 | 保留海报预览和长按保存 |
| 新功能破坏现有界面 | 保留当前主界面，只增加状态和入口 |
| 平台 API 存在差异 | 所有平台调用集中在适配层并做能力检测 |
