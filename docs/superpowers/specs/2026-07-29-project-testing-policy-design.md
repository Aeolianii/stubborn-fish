# 项目测试策略分级设计

## 目标

在项目级 `AGENTS.md` 中覆盖上级通用测试驱动开发规则，避免微小、低风险改动被强制要求设计并补写大量失败测试，同时保留重大修改的测试保障。

## 规则设计

新增“测试与变更分级”章节，并明确以下规则：

- 本项目的测试流程以项目级规则为准。
- 只有重大修改需要在实施前与用户确认测试范围和测试设计；确认后先编写并运行失败测试，再实现功能。
- 重大修改包括核心玩法、关键用户流程、状态或数据结构、API 契约、跨模块逻辑，以及具有较高回归风险的缺陷修复。
- 文案、样式、资源替换、简单参数调整和低风险局部逻辑等小改动，不强制进行测试设计确认，也不强制先写失败测试。
- 小改动仍需进行与风险相匹配的最小验证，例如现有测试、静态检查、构建检查或针对性手动验证。
- 禁止仅为满足流程而给小改动补写大量无关测试。
- 边界不清时根据影响范围和回归风险判断；只有很可能属于重大修改时才询问用户确认。

## 验收标准

- `AGENTS.md` 清楚说明该规则覆盖上级通用 TDD 要求。
- “重大修改”和“小改动”均有具体、可执行的示例。
- 重大修改保留“先确认测试设计，再写失败测试”的流程。
- 小改动不再默认触发测试设计确认或失败测试。
- 所有改动仍需进行与风险匹配的验证。
